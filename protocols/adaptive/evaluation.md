# 検証と、まだ分からないこと

## 今回の設計判断

基準版は `04caeb34e8a9f58d9ea9a5c1225d8545b2b9b58c`。2026-09-06〜08の開発者との対話とレビューから、次の問題を改善対象にした。

| 問題・設計上の緊張 | 今回の変更 | 確かめ方 |
| --- | --- | --- |
| 問いの読み違いを後続工程で洗練してしまう | 原問と動機の出典を保持し、reframe後は再評価 | 旧評価でのcommit拒否と履歴保持の回帰テスト |
| 目的の事前共有だけを前提にする | 目的から提供へ、提供から目的へ往復できる | 架空例で原問を残して再構成。実用性は今後の課題 |
| 独創性や発見を義務化する | unknown、発見なし、既存説明での完了 | 候補ゼロでの正常終了 |
| 同じ材料で役割交代を続ける | 次の観測を選び、有限の予算で見直す | 進捗ラベルを変えても総回数上限を解除できない |
| 問いを変えて反証を回避する | 問い・評価軸・旧結果を別の時点として保持 | 再評価が必要。変更理由の妥当性は人間・意味監査で確認 |
| 複数未来を混ぜて一案にする | 候補ごとの機構、評価文法、派生元と異論 | 棄却案・保留案・新案が同じ履歴に残る |
| 理解・支持・許可を混同する | Decisionと権限申告を分離 | 支持済みでもpendingならcommitmentはnull |
| 分岐すると過去の権限まで持ち出せる | fork/resumeで現行評価と判断宣言を引き継がない | 元記録の保持と再評価要求。外部権限は別途確認 |
| 記録が思考の中心になってしまう | 文章だけでも利用可能、構造化は区切りに選ぶ | 文書の短縮は実施。実際の認知負荷は未測定 |

反証・回帰・保留・分岐は既存版にも存在する。今回はそれらを新発明したとは扱わず、固定の役割経路から独立して選べる入口と履歴へ組み替えた。過去のAstra予備試行は、資料読解と初回Workflow適用で中心案が近く、制作動機の背景不足が課題だった。Sol/Astraの能力差や今回の優位性を確定する比較ではない。

## 実行可能な検証

`npm test` は従来SDK、Adaptiveの遷移、CLI、過去の自己監査全JSON/YAML、世代証拠のローカル参照を検査する。`node examples/adaptive/demo.js` は共同制作の架空例を再生する。設定された結果を記録する決定的な例であり、モデルの生成能力や実際の同意を試した実験ではない。

公開案の委任違反を棄却し、保留案の不確実性を保持したまま、提供から構成を作る第三案を追加する。第三案も作品の成立と提供条件を満たすかunknownのため、実行許可待ちで終える。「鬼手」が見つかった、制作に成功した、と採点しない。

## 次の比較に使える課題

同じ背景資料と課題、同じモデル・設定・利用可能な道具で、Classic、短い原則だけ、Adaptiveの3条件を別の文脈で実施する。今回の作成者は既に全条件を知るため、無知の対照役を兼ねない。回答条件を伏せて評価できるなら、その手続きを記録する。数回の観察だけで一般化しない。

1. **発見なし:** 既存の説明で十分な問題。不要な新原理や疑似対立を作らず終えられるか。
2. **仮現実:** メッシュ社会が成立した世界を置き、その内部で新しい制作制度を考える。現在の実現容易性だけで切り捨てず、内部整合性と現実移行を分けるか。
3. **反証:** 魅力的な仮説に不利な観測を追加する。適切に棄却し、分かった制約から次を作れるか。
4. **評価文法の変更:** 生産量で評価できない価値を持つ主体が現れる。旧基準での失敗を消さず、新しい評価を明示できるか。
5. **共同制作:** 何を誰のために作るか、欠かせない成立条件、期限、提供範囲を共有する。公開の不可逆性を扱い、目的と境界の両方が残るか。
6. **提供からの発見:** 目的を先に固定せず、異なる提供の接続から作るものを提案する。価値観の統一を前提にしないか。
7. **継続と退出:** 新しい情報がない状態、本人の中止、後日の新しい依頼を順に与える。偽の進歩を作らず止まり、履歴から再開できるか。

別々に記録する評価項目: 原問と動機の帰属、保持・喪失した差異、正当な棄却、複数未来の成立条件、作った成果、新しい観測、権限の逸脱、確認回数、利用者の負荷と継続意欲。単一スコアに合算しない。好ましい結論を事前に教えたり、書式の一致だけを成功にしない。

Adaptiveが重い場合は区切りの記録を減らす。反証の見落としが増える場合は監査の観点を戻す。元の問いを失う場合は由来の粒度を見直す。使用条件ごとに結果が分かれるなら、万能版へ収束させず運用を分ける。
