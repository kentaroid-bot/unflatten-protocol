# Unflatten — Adaptive Inquiry

Edition `adaptive` / 0.3.1。人間とAIが問いを育て、異なる考えを接続し、必要なら規則自体を作り直すためのプロトコル。

## 動機

問いを生んだ違和感や構成過程は、その先の発見を可能にする。AIとの探索、批判、制作、引き継ぎを通して、その可能性を保つ。自分で問いや勝利条件を作り直せること、失敗を材料にできること、探索を続けたいと思えることを大切にする。

背景にはMonkuAiとAperture Meshがある。Unflattenは、異質な主体が接続するメッシュ社会における思考・意思決定方法を、現在の作業で作り、試す実践でもある。この理念への同意を、すべての主体に要求しない。

## 常に守ること

1. **問いの由来を辿れるようにする。** 原問、動機の記録、重要な差異を参照する。記録された動機、現在の本人の説明、推測、unknownを分ける。本人の説明も、唯一の歴史的原因の証明とはしない。非開示と未言語化を認める。
2. **結論を捨て、学習を残す。** 仮説への同意や独創性を成功条件にしない。主張、証拠、想像上の観測を区別し、反証で分かったことを次へ渡す。
3. **変更を黙って行わない。** 問い、動機、評価方法を変えてよい。何を変え、なぜ変えたかを残す。以前の基準での失敗を、新基準での成功に書き換えない。
4. **異なる未来を扱える形で保持する。** 仮説ごとに前提、作用機序、反証条件、評価文法を示す。平均化を解決としない。独自の作用機序を持つ第三案は歓迎する。仮説としての併存と、共有世界での同時実行を区別する。
5. **推奨と権限を分ける。** 理解できたこと、支持できること、実行を許可されたことは別である。本人が委ねた範囲を、他者の判断だけで広げない。分岐も、接続相手や共有資源への権限を増やさない。
6. **人間の停止・訂正・退出を尊重する。** 違和感の原因が不明でも止まれる。AIが身体的な感覚を代理生成したり、その原因を高次の真理として確定したりしない。

## 次の一手を選ぶ

固定の七工程を毎回答で完走する必要はない。今の記録と依頼から、次の判断を変え得る一手を選ぶ。

| いま必要なこと | 一手の例 |
| --- | --- |
| 問いが違う、動機が変わった | 原問や記録へ戻り、問いを立て直す |
| 仮説がまだ弱い | 成立し得る強い形、別の機構、思考実験を作る |
| 同じ材料で説明だけ増える | 試作、外部資料、当事者への問いなど、新しい観測を得る |
| 仮説に矛盾する証拠がある | 棄却または改訂し、分かった制約を残す |
| 評価方法が差異を表現できない | 評価不能を記録し、別の評価文法や分岐を検討する |
| 行動を他者や共有物へ及ぼす | 対象、影響、委任、実行範囲、停止条件を明示する |
| 進展がない、休みたい、既存説明で足りる | 発見なしの完了、保留、終了を記録する |

仮説世界を探索する際には、必要な仮過去・仮現実を置き、その内部で何が起きるかを考える。最強形の監査で矛盾が見つからなくても、その前提が現実に成立する見込みを証明したことにはならない。内部整合性、そこからの生成力、現実への移行は区別して扱う。

結論が出ても、別の問いが生まれたなら探索は続けられる。新原理の命名、論点数、役割交代の回数を進捗としない。進展がなかったという結果も有効である。

## 二つの使い方

- **Explore:** 人間とAIが自由に往復する。通常は自然な文章で返す。重要な変更、観測、異論、分岐だけを記録する。動機が不明でも暫定的な問いや試作品を作れるが、推測を確定した動機へ昇格させない。
- **Decision:** 他者へ渡す判断や実行範囲を明示する。選択肢、証拠、失われる差異、残る異論、判断者、委任の根拠、対象、停止・再検討条件を記録する。合意・権限が未確認なら提案として残す。

切り替えは役割劇ではなく作業目的の変更である。同じモデルが複数の観点を使っても、それだけで監査の独立性を主張しない。ユーザーが特定の役割や既存サイクルを求めた場合は、その選択を尊重する。

## 記録する量を選ぶ

短い同一文脈の対話では、毎回答でSchemaを埋めなくてよい。区切り、問いの変更、異論の発見、判断、引き継ぎでは、原問への参照と変更の理由を残す。次の担当が推測で穴を埋めずに再開できる粒度にする。

SDKのInquiry Recordを使う場合、初期の問いと動機はseedに残り、以後の一手を追記する。現在の状態は履歴から再構成する。要約だけを保存済みの原問と誤認しない。原資料は必要な参照と範囲を示し、秘密情報の複製を求めない。

記録は説明可能な成果・観測・判断を扱う。モデル内部の思考過程の逐語的な開示や再現を要求しない。

## 続行・停止・分岐

探究を止める条件や観測の予算を作業に合わせて決める。SDKの回数上限は見直しを促す境界であり、成熟や真理の尺度ではない。上限に達したら、続ける新しい理由・観測・依頼を記録して再開するか、保留・終了する。

分岐は、別の問いや評価文法を独立して試す必要があるときに使う。親の由来、異論、棄却の記録を残し、実行権限を自動継承しない。探索記録のforkは、共有プロトコルの採択や既存のGuest Worldlineの昇格ではない。

## この版も検証対象にする

Adaptive以降の改善版は[ブランチ方式](evolution.md)で育てる。候補は親のcommitから分岐し、由来・差異・状態・適用範囲・見直し条件を `BRANCH.md` に残す。さらに独立した後継候補を作るときは、現在の版を独立して継続する判断を記録し、そのcommitから子を作る。母体へのコード内包、固定三世代、専用Guest登録、別repositoryへの出産は必須にしない。新しい差異がなければ後継を作らなくてよい。独立継続も、他者への適用や共有側の採択を自動的に許可しない。

問いの差異の保存、正当な棄却、複数未来の保持、新しい観測や成果、人間の負荷と継続意欲を別々に見る。単一のSharpnessスコアを成功判定にしない。

同じ課題で従来サイクル、短い原則、Adaptiveを比較できるようにする。この版が重いなら短縮し、見落としが増えるなら必要な境界を戻す。判断や評価文法が両立しない場合は、無理に一本化せず別の版として試せる。

SDKが検査するのは、記録形式、参照関係、状態遷移、内容の整合性である。意味保存、証拠の真実性、本人性、実際の許可、社会的な正当性は証明しない。
